# 2026.301.1748 — docs(check): the authoring-gotchas reference names the knob that exists

## Summary

Head `0d5340a9bec82a533677957ff26cc88e24bcd30a` — **1 file changed, 1 insertion(+), 1 deletion(-)**.

The `check` family's `authoring-gotchas` reference named the **retired** `--podman-jobs` flag as an example of a speed lever that does not shrink scope:

```
authorization. Speed levers that do not shrink scope (e.g. `--podman-jobs`, `--jobs`) need
```

That flag was retired by the BuildKit cutover. The contract's spelling is `stage_parallelism` / `stage_parallelism_cap`, and the CLI that accepts it is `--stage-parallelism` / `CHARLY_STAGE_PARALLELISM`. The line now names the knob that exists:

```
authorization. Speed levers that do not shrink scope (e.g. `--stage-parallelism`, `--jobs`) need
```

**Why this is not a cosmetic rename.** This body is published: `layer-charly-check` owns the `check` family's `skill:` entities, `charly marketplace generate` projects them into the corpus, and every harness that loads the corpus reads them. A reader who followed the sentence literally passed `--podman-jobs` to a CLI that **rejects the flag at the parse boundary** — the same defect opencharly/charly#1081 was, where the shipped binary compiled in a plugin-box whose box-build grammar still spelled the knob `--podman-jobs` and the contract's `--stage-parallelism` was rejected with exit 80. The producer leg that renamed the flag is opencharly/plugin-box#66, merged as `v2026.301.1542`.

**What does NOT change.** The outer `--jobs` lever named beside it stays: it is the per-DAG-level image concurrency, and it is still alive (`--jobs` / `CHARLY_BUILD_JOBS`, `defaults.jobs`). Only the inner knob's spelling changes.

This is the `opencharly/layer-charly-check` leg of the `stage_parallelism` fan-out tracked in opencharly/opencharly#785; that tracker's table names this repo's site as `charly.yml:709`.

Closes #54.
