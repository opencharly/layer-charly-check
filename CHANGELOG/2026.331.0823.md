# 2026.331.0823 — feat(skills)!: retire the adb, android, appium and jetkvm check cards

## Summary

Retire the four Android/JetKVM check-family skill cards from `layer-charly-check`,
the owning repo of the `charly-check` skills. This is the `layer-charly-check` leg
of the org-wide retirement `opencharly/opencharly#1318` (operator decision
2026-11-27, no replacement): Android and JetKVM are removed completely.

Removed:

- The four `skill:` nodes in `charly.yml`: `adb-skill`, `android-skill`,
  `appium-skill`, `jetkvm-skill` (routing metadata gone with them).
- The four bodies: `.agents/skills/adb/`, `.agents/skills/android/`,
  `.agents/skills/appium/`, `.agents/skills/jetkvm/` — 4 files, 1,157 lines.
- The `check` card's `adb:` / `jetkvm:` / `appium:` trigger items.

Swept so no surviving page references a removed card:

- `.agents/skills/check/SKILL.md` — the out-of-process verb list no longer names
  the `adb:`/`appium:` verbs or their plugins; the dangling "For Android UI
  readiness … `/charly-check:adb`" guidance in the check reference prose is gone.
- `.agents/skills/console-automation/SKILL.md` — the JetKVM-specific clauses are
  removed (the `plugin-jetkvm` transport row, the `kind: jetkvm` sentence, the
  `jetkvm:`-keyed YAML examples, the `/charly-check:jetkvm` cross-reference, and
  the "over a JetKVM (USB HID)" phrasing). The generic transport-neutral
  SPICE/console half — `sdk/kit` ConsoleTransport/ConsoleWizard/ConsoleSession/
  ConsoleFlow, `plugin-spice`, open-terminal/run-command/close-terminal,
  luks-unlock, `flow`, boot-order, the OCR/upscale and measured-hardware sections —
  is KEPT intact.
- `.agents/skills/cua/SKILL.md` — the `jetkvm:` sibling mention is dropped from
  the dispatch-path list (`wl:` / `record:` remain).
- `README.md` / `AGENTS.md` — the owned-entity census and node list move from 14
  to 10 (`check`, `cdp`, `check-sway-browser-vnc`, `dbus`, `libvirt`, `record`,
  `spice`, `vnc`, `console-automation`, `cua`).
- `charly.yml` prose that named the removed words where it had become false: the
  `check-android-emulator-pod` bed row, the `kind ∈ {pod, vm, local, android}`
  load-time-guard kind list (now `{pod, vm, local}`), the
  "Candy / box / pod / vm / kubernetes / local / android config" validation row,
  the reserved-kind-word rule's kind list (now without `android`), and the
  console-automation trigger's "shared between JetKVM and VM (SPICE)" clause.

No surviving skill (cdp, wl, wl-overlay, dbus, vnc, spice, libvirt, record,
punktfunk, quickshell, mcp, kube, display, kvm) was removed or reworded.

The marketplace corpus (`marketplace/check/skills/...`, `marketplace/DISPATCHER.md`)
is a generated projection and is regenerated by the programme's marketplace leg;
it is deliberately not hand-edited here.

Relates to opencharly/opencharly#1318.
