# 2026.277.1722 — docs(check): mirror Standard 8 for a compiled-in plugin (--dev-plugin)

## Summary

Standard 8 of the `check` skill's `beds-and-r10` reference states the R9 rule for a **plugin binary** — a
verb served OUT-OF-PROCESS runs the packaged plugin unless `CHARLY_PLUGIN_DIR` points at your build — and
that statement does not generalise. The case whose remedy it cannot reach is the **compiled-in** plugin: a
candy named in charly's `compiled_plugins:` is linked into `bin/charly`, so a bed run on a stock binary
cannot fail on an unmerged compiled-in plugin *at all*. This PR adds that mirror case to Standard 8.

This is the documentation leg of `opencharly/charly#775` (scope item 1); the mechanism itself landed as
`opencharly/charly#788` (merged 15:28:14Z, tag `v2026.277.1528`). **#775 stays open** — it needs this PR,
the compiled-in-candy recipe pointer (leg 2), and the marketplace regeneration (leg 3).

What the new text adds, in three parts:

1. **Why the existing remedy cannot reach it** — `CHARLY_PLUGIN_DIR` is read only by the out-of-process
   loader, and `CHARLY_REPO_OVERRIDE` re-points the candy resolver / local plugin source, not the Go module
   graph of a compiled-in build.
2. **The sanctioned override** — `scripts/bootstrap-charly.sh --dev-plugin <candy-name>=<repo-checkout>`,
   what it writes (`go.work.dev`, selected only under an explicit `GOWORK=`), and the two validations the
   generator runs before any compilation.
3. **How to assert the changed path EXECUTED** — the two traps that have each shipped a false green:
   the `go version -m` `(devel)`-vs-module-proxy discriminator (necessary, not sufficient), and a symbol-set
   difference over `go tool nm` instead of a package-anchored `grep` (which matches every plain function and
   no method at all).

Scope: **43 lines of prose inserted into one `content:` scalar**, zero deletions, no other reference, no
skill-level content, no plan step, no pin, no script. `git diff --shortstat` → `1 file changed, 43 insertions(+)`.
