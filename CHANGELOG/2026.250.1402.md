# 2026.250.1402 — docs(check): document the mcp: verb VM/host venues + the HOST_PORT VM runtime vars

## Summary

Document the **new mcp: verb VM/host venues** and the **addr: VM runtime vars** in the `check-skill` reference skill (layer-charly-check):

1. **`live-probe-verbs` inline file → `### Method allowlist — mcp`**: the `mcp:` verb is now documented as substrate-neutral. A container venue resolves its `mcp_provide` declarations from the `ai.opencharly.mcp_provide` OCI label; a VM/host venue has no podman-inspectable label — the label leg fails ("container for %s is not running") — so the runner falls back to the `mcp_provide` the check env threads from the project's template (plugin-mcp `effectiveMCPProvides`). For a VM venue the threaded declaration is host-routable: the persisted `network.port_forwards` auto-forward allocations rewrite a loopback `mcp_provide` URL to `127.0.0.1:<forwarded-host-port>` (plugin-check `mergeVmForwardedHostPortVars` + `hostRoutableMcpProvide`), so the dial reaches the guest's MCP server through the forwarded port. The `check-cachyos-mcp-vm` bed is called out as the standing example.

2. **The verb-catalog file entry → `## Runtime variables`**: the `HOST_PORT:<guest>` var grammar is now documented as threaded for VM venues too — a VM's declared `network.port_forwards` host ports (the persisted auto-forward allocations, read via the reverse channel) resolve as `HOST_PORT:<guest>` runtime vars; a fixed forward needs no var. `addr: 127.0.0.1:${HOST_PORT:<guest>}` therefore resolves for VM beds (e.g. the fixed-forward dial in `check-cachyos-mcp-vm`), matching the pod-bed grammar.

All statements verified against the merged code: plugin-check @ origin/main (#35 — `candy/plugin-check/vm_port_forward_env.go`, `live_gather.go` VM path), plugin-mcp `candy/plugin-mcp/resolve.go` `effectiveMCPProvides`, and distro-cachyos `charly.yml` `check-cachyos-mcp-vm` + the cachyos-vm `mcp_provide`/fixed `18765:18765` forward.
