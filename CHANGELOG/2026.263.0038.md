# 2026.263.0038 — docs(skill): codify the golden keeper-stop invariant in the check skill

## Summary of changes

R1: codify the **golden keeper-stop invariant** in the `check` skill prose (`charly.yml`), matching the merged bed-runner behaviour (`opencharly/plugin-check#52`).

A bed with `snapshot: {on_finalize: <name>, mode: external}` (`keep_venue: true`) captures a golden at install finalize and re-uses it as the shared clone SOURCE for anchored lanes (`from: <bed>:golden`). The capture creates an EXTERNAL snapshot whose disk is the clone backing; a running keeper domain holds an exclusive qemu write lock on it, so every clone that opens it as a read-only backing fails with `Failed to get shared "write" lock`. `keep_venue: true` suppresses the teardown's `vm destroy`, so the release MUST be an explicit step — the runner emits `snapshot-stop-keeper` (`vm stop <entity> --domain <bed-domain>`, idempotent). The capture and the keeper-stop share ONE predicate (`capturesGolden`).

The doc records this where the check skill's snapshot/golden guidance lives, so a future bed author does not re-introduce the hang.
