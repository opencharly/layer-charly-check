The `description:` deletion is deliberate: `sdk/deploykit/skills_collect.go` assigns
`entry.Description = s.Description` **only** on its `sf == nil` branch (the transitional in-line form) and
overwrites it from the file unconditionally once a body exists, so the node field is unreachable after the
move and would be a second copy of the same prose.

**The five `content:` blocks that survive this unit are named, and they are not skill bodies.** All five
are the `check` node's `references:` entries — `authoring-gotchas`, `beds-and-r10`,
`cross-deployment-probing`, `live-probe-verbs`, `verb-catalog`. The generator projects a reference from the
node and only falls back to `references/<stem>.md` files when the node declares none
(`if len(entry.References) == 0`), so relocating them is a different change; `#48` moved that node's body
and left the references, and no unit of this leg touches them.

### The two prose surfaces, and why they move here

`AGENTS.md` said "The `skill:` entities are the projected usage source. Edit them here" and listed the
fourteen as `entities`; `README.md` said the same. After the body move both are stale instructions, so this
unit retargets them to the file-plus-node split and to the `.agents/skills/<name>/SKILL.md` entry. They are
in the last unit rather than the first because they describe the post-cutover shape, which only exists once
the last unit lands. R5's claim-keyed sweep for the retired sentences is pasted below with its exit codes.

### Why beside the owning candy

`sdk/deploykit/skills_collect.go` resolves a body as `filepath.Join(layer.GetSourceDir(), ".agents/skills")`
— the directory of the candy that declares the node — and `candywalk.ReadSkillFile` reads
`<that tree>/<name>/SKILL.md`. In this repository the declaring candy is `charly-check`, whose manifest *is*
the repo-root `charly.yml`, so `.agents/skills/` at the repo root **is** the tree beside the owning candy.
That is also why the negative control moves a body *out of* that tree rather than "to the repo root": here
those two paths are the same place.
