The R10 change-class matrix (this skill is its registered SOLE owner) enumerated
six classes and NONE for a contract/library Go module — a module with no
`charly.yml` project, no `main`/deployable target, therefore no `disposable:
true` entity (the `github.com/opencharly/spec` + `github.com/opencharly/sdk`
contract modules; any standalone library repo).

**Why the row is needed.** Merged `spec` PRs (#143/#144/#145) correctly used the
module's own committed CI (`.github/workflows/ci.yml`: build + test + gofmt +
golangci-lint) as their gate and answered `R10 — N/A — no disposable deploy
target`, but the reviewer had no provision to cite for that class — every round
requested "the R10 change-class-matrix provision that sanctions the module suite
for a contract/library module, or an explicit maintainer sign-off". This adds
the provision.

**The row:** the module suite IS the gate (no bed CAN exist — a bed that cannot
fail on the change proves nothing, the matrix's own opening principle); the
suite must genuinely EXECUTE the changed paths (a test that would FAIL without
the change); the no-disposable-target premise is proved with executed output
(`git ls-files | grep -c 'charly.yml'` → 0; `git grep -c 'disposable: true'` →
no match); a consumer-boundary change rides the consumer PR's bed (B6). Tier:
`fully tested and validated`. Explicitly NOT required: a `charly check run` bed
in the module repo.
