# 2026.242.2213 — docs(skills): the wl skills leave — they belong to the plugin that serves them

## Summary

`wl-skill` and `wl-overlay-skill` documented the `wl:` check verb **from here** — a repo that
ships none of its code. The verb, its 45-method allowlist, its CUE schema and its dispatch
all live in `opencharly/plugin-wl`; only the documentation lived here, so every method added
there left the skill quietly behind.

The cost was already paid, and measurably: the skill documented `sway-*` and `overlay-*` and
had **no mention of the `hypr-*` family at all**, which plugin-wl has served for some time. A
reader following it would conclude Hyprland is unsupported.

`plugin-punktfunk` is the precedent — `punktfunk-skill` is a sibling node in its own candy
manifest with `family: check, owner: plugin-punktfunk`. The two wl skills now match it.

`family: check` is unchanged on both, so they still publish to `check/skills/wl/` and
`check/skills/wl-overlay/`, and every `/charly-check:wl` cross-reference in the skills that
remain here stays valid — **family decides the published path, `owner:` decides which image's
OCI label carries the skill**.

This repo keeps the 11 skills whose verbs it still owns: `adb`, `android`, `appium`, `cdp`,
`check`, `check-sway-browser-vnc`, `dbus`, `libvirt`, `record`, `spice`, `vnc`.

## Landing order — this is the second of three PRs

The published corpus is generated from an **authored refs list** in
`opencharly/marketplace` (`candy/charly-marketplace/charly.yml`, ~180 pins). A repo not in
that list contributes nothing, and **`plugin-wl` is not currently in it**.

1. **`opencharly/plugin-wl#7`** — adds the two skills there. **Merged and tagged before this
   PR.** Corpus unchanged at that point, because plugin-wl is not yet a ref.
2. **This PR** — removes them from here.
3. **`opencharly/marketplace`** — ONE PR that bumps this repo's pin **and** adds
   `@github.com/opencharly/plugin-wl/candy/plugin-wl:v<tag>`.

Step 3 must not be split: a skill `name:` is marketplace-globally-unique, so adding the new
ref while this repo still carried the skills would put two `wl` skills in one generation, and
this PR merging without step 3 following would drop them from the corpus until it does. That
window is why the marketplace PR is a single change and why it comes last.
