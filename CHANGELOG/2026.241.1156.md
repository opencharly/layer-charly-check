# 2026.241.1156 — feat: extract the charly-check candy into its own repo

## Summary of changes

Phase D of the approved cutover: extract the `charly-check` candy out of `charly/candy/` into its own
kind-prefixed repo.

`charly/candy/` is the marketplace corpus's **second input path** — it reaches the corpus only
because CI clones charly at a hand-written tag, which is how a stale pin can freeze skill content
while every gate stays green. Emptying it removes that path. This candy owns **13 `skill:`
entities**.

| File | Notes |
|---|---|
| `charly.yml` | the candy **verbatim** from `charly/candy/charly-check/charly.yml`, with the file-level `version:` line prepended (5532 → 5533 lines) |
| `README.md` | states the `SKILL.md` are generated into the marketplace, not edited here |
| `.github/workflows/{deploy,pr-validator,tag-on-merge}.yml` | the standard three dispatchers |

**No skill content is edited.** The move must be byte-identical in the generated corpus — that is
the gate on the move, and it only means anything if the move is a pure copy. Content corrections
follow separately, after the move is proven.

### Two stale values deliberately NOT copied from the template

Every existing candy repo declares `version: 2026.232.0520` and pins CI at charly
`v2026.238.1242`. Both are stale: current charly requires schema **`2026.240.1943`**, and those
repos stay green only *because* their CI pin is old enough not to notice. Copying the template
verbatim would have imported both. This repo declares the current schema and pins the current
charly tag (`v2026.241.1121`).
