# 2026.293.1934 — feat(skills): cdp, check and check-sway-browser-vnc bodies move to `.agents/skills` (2 of 4)

## Summary

**Slice 2 of 4** of the `check` family's skill-body relocation (`opencharly/layer-charly-check#45`). The
fourteen `skill:` nodes in `charly.yml` carried their prose inline as `content:` blocks; this slice moves
the next three bodies — `cdp`, `check` and `check-sway-browser-vnc` — into the files the repository owns,
at `.agents/skills/<name>/SKILL.md`, and leaves each node carrying only its routing metadata.

Its siblings are `#47` (slice 1) and `#49`/`#50` (slices 3 and 4); each is reviewed on its own diff. The
split is a review-capacity decision: `opencharly/layer-charly-check#46` already carries the whole change and its **one**
verdict is not a finding — it is the review engine reporting `finish_reason="length"`, i.e. that it spent
its output budget on reasoning over a 5783-insertion diff. This PR supersedes that PR's slice of the change.

Diff against `main`: **965 insertions and 956 deletions across 4 files** — three new `SKILL.md` files and
the manifest, from which **3 skill-owned `content:` blocks** are deleted along with the **3 `description:`
blocks** on the same nodes. The description deletion is deliberate: `sdk/deploykit/skills_collect.go`
assigns `entry.Description = s.Description` **only** on its `sf == nil` branch (the transitional in-line
form) and overwrites it from the file unconditionally once a body exists, so the node field is unreachable
after the move and would be a second copy of the same prose.

**The `content:` blocks that survive are named.** Five remain, and all five are the `check` node's
`references:` entries — `authoring-gotchas`, `beds-and-r10`, `cross-deployment-probing`,
`live-probe-verbs`, `verb-catalog` — printed back from the committed manifest in the evidence below. They
are not skill bodies: the generator projects a reference from the node and only falls back to
`references/<stem>.md` files when the node declares none (`if len(entry.References) == 0`), so relocating
them is a different change and this PR does not touch them. The `check` node is the one node in this slice
whose key set therefore keeps `references` after the move.

### Why beside the owning candy

`sdk/deploykit/skills_collect.go` resolves a body as `filepath.Join(layer.GetSourceDir(), ".agents/skills")`
— the directory of the candy that declares the node — and `candywalk.ReadSkillFile` reads
`<that tree>/<name>/SKILL.md`. In this repository the declaring candy is `charly-check`, whose manifest *is*
the repo-root `charly.yml`, so `.agents/skills/` at the repo root **is** the tree beside the owning candy.
That is also why the negative control moves a body *out of* that tree rather than "to the repo root": here
those two paths are the same place.
