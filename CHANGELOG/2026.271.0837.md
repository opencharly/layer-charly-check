# 2026.271.0837 — docs(skill): correct the check-step never-hang bound (90s -> 120s) + nested-lease case

## Summary

Corrects the `check` skill's gotcha #13 and adds a second measured cause.

**Doc-vs-reality divergence (R1).** #13 claimed every probe attempt is bounded
at `runnerProbeNeverHangFallback` = **90 seconds**. That constant is only the
bare-`NewRunner` guard (a test / a plugin). The live `charly check` path sets
`cfg.ProbeTimeout` from the readiness table —
`poll.ReadinessProvider().PerAttemptFor(PollLocal)`
(`candy/plugin-check/plugin_runner.go`, repo-root-relative) — whose class
fallback is `readinessPerAttemptFallback` = **120 seconds**
(`spec/poll/poll.go`). The section now instructs reading the bound out of the
kill message rather than assuming it.

**A second measured cause.** A full nested-container acceptance loop — e.g.
`cbx-e2e-loop`, which leases a real nested container via `local-container`,
syncs a git workdir and streams a command — has minutes-long work of its own
and exceeds the bound with nothing wedged. Bound it with an explicit `timeout:`.
