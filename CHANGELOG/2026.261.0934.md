# 2026.261.0934 — docs(skill): document JETKVM_HOST and the move/click button semantics

## Summary of changes

Documents the input/interface behaviours the plugin fix (`opencharly/plugin-jetkvm#5`) establishes, in the `jetkvm` skill entity (`charly.yml` → `jetkvm-skill` → "Connection details").

- Device address resolves **authored `host:` → `JETKVM_HOST` → deploy venue**; authoring no `host:` with `JETKVM_HOST` set keeps a device-specific hostname out of a committed plan (the pattern `JETKVM_AUTH_TOKEN`/`JETKVM_PASSWORD` already use).
- `move`/`mouse` are always a pure position move (an authored `button:` is validated, never sent); `click`/`drag` press the button, defaulting to `left`.
- `x`/`y` (and `from_x`/`from_y`) are **absolute HID coordinates `[0,32767]`, not desktop pixels**, with the pixel→HID conversion.
- `key`/`key-combo` resolve over the full USB HID Keyboard/Keypad usage table (letters, digits, `F5`, `Up`, `Delete`, chords), so arbitrary names work.

**Closes / relates to:** `opencharly/plugin-jetkvm#5` (code + removed hostname leak). The marketplace corpus regeneration is a separate follow-up PR that consumes THIS repo's merge tag.

**Breaking change + rollback:** `none` — skill prose. Revert the merge to roll back.
