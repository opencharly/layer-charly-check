**Slice 3 of 4** of the `check` family's skill-body relocation (`opencharly/layer-charly-check#45`). The
fourteen `skill:` nodes in `charly.yml` carried their prose inline as `content:` blocks; this slice moves
the next four bodies — `dbus`, `libvirt`, `record` and `spice` — into the files the repository owns, at

land in a single atomic commit" by splitting it "into ordered units as FORWARD MOTION only". The single
atomic landing was attempted FIRST and is open as `opencharly/layer-charly-check#46`; its **one** verdict is
not a finding but the review engine reporting `finish_reason="length"` over that 5783-insertion diff, "NOT
retryable with the same max_tokens/reasoning_effort". `#45` stays open until the last unit lands, and no unit

Diff against `main`: **1045 insertions and 1036 deletions across 5 files** — four new `SKILL.md` files and

blocks** on the same nodes. The description deletion is deliberate: `sdk/deploykit/skills_collect.go`

form) and overwrites it from the file unconditionally once a body exists, so the node field is unreachable
after the move and would be a second copy of the same prose.

**The `content:` blocks that survive are named.** Five remain, and all five are the `check` node's
`references:` entries — `authoring-gotchas`, `beds-and-r10`, `cross-deployment-probing`,
`live-probe-verbs`, `verb-catalog`. That node is not in this slice; it belongs to `#48`, which keeps those
references inline on purpose: the generator projects a reference from the node and only falls back to
`references/<stem>.md` files when the node declares none (`if len(entry.References) == 0`). Relocating them
is a different change, and no PR in this cutover touches them.

### Why beside the owning candy

`sdk/deploykit/skills_collect.go` resolves a body as `filepath.Join(layer.GetSourceDir(), ".agents/skills")`
— the directory of the candy that declares the node — and `candywalk.ReadSkillFile` reads
`<that tree>/<name>/SKILL.md`. In this repository the declaring candy is `charly-check`, whose manifest *is*
the repo-root `charly.yml`, so `.agents/skills/` at the repo root **is** the tree beside the owning candy.
That is also why the negative control moves a body *out of* that tree rather than "to the repo root": here
those two paths are the same place.
