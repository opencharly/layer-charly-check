# 2026.269.1154 — feat(skill): add the cua check-family skill entity

## Summary

Adds the **`cua` skill entity** to the charly-check concept candy: the R0-dispatcher entry
point for the `cua:` computer-use verb, the `kind: cua` entity, and the `container_disk` VM
source. Its triggers route an agent from "drive a live desktop through Cua Driver" / "a Cua
Fleet image / KubeVirt containerDisk" to this procedure rather than to source-diving.

Content covers: what `cua:` is (an out-of-process plugin verb, not a host subcommand); the
CLI-over-MCP-transport choice; the read-only-by-default `allow_control` safety gate; the
full method catalog split read-only vs mutating; the foreground/background delivery modes;
and the `container_disk` VM source that pulls + boots a KubeVirt containerDisk (a Cua Fleet
image) locally.

The repo was on schema `2026.240.1943`; `charly migrate` moved it to `2026.261.1747` (the
one-line `version:` change — required because the current charly rejects the older schema).

### Review-round fix (this head)

**A3 — the changed surface is now proven to LOAD and be VALIDATED at runtime.** The `cua`
skill entity is a `kind: skill` node; the changed surface is the loader's `plugin kind:skill`
decode path. A `charly` binary built from this change's worktree was run against the
`charly.yml`, exercising that path in **both** directions:

**Positive** — the entity decodes and the project validates:

```
$ charly -C <worktree> box validate
charly box validate: OK — checked 1 candy, 7 distros, 7 builders; 0 warnings, 0 errors
```

**Negative control** — mutating the `cua-skill` node's `name` to violate `#Skill`'s
`^[a-z][a-z0-9-]*$` pattern makes the binary **reject it, naming the node** (proof the
entity is actually decoded by the shipped surface, not ignored):

```
$ charly -C <worktree> box validate      # with cua-skill.name: Cua
charly: error: command "validate": validation error: …/charly.yml:doc0:
  node "cua-skill": plugin kind:skill: plugin_input fails #SkillInput:
  #SkillInput.name: invalid value "Cua" (out of bound =~"^[a-z][a-z0-9-]*$")
```

That is the changed artifact (the skill entity) executing through the loader in a built
binary — the schema check plus a fail-proving control, not a schema-only check.

> Note: the marketplace GENERATOR (`charly marketplace generate`) reads skill entities from

> unlanded worktree without a tag; the loader decode above is the direct runtime proof the
