# 2026.261.1057 — docs(skill): narrow the key resolver coverage claim to the supported HID set

## Summary of changes

Corrects a doc-vs-reality overstatement in the `jetkvm` skill entity's "Connection details": after the input-semantics extension (layer#15), the text said `key`/`key-combo` resolve over the "**full** USB HID Keyboard/Keypad usage table, so **arbitrary names work**". The implemented resolver (`opencharly/plugin-jetkvm`, `internal/kvmclient/keymap.go`) covers a **curated common set** — letters `a`–`z`, digits `0`–`9`, `F1`–`F12`, navigation/editing keys, punctuation, modifiers — and rejects anything outside it with `unknown key` (e.g. `F13`+, keypad usages, media keys). The text now states that set and that names outside it fail.

The same edit adds the **`charly-jetkvm env` flow** to the "Running charly ON the device" section (from the merged `opencharly/charly-jetkvm#1`): `eval "$(charly-jetkvm env --host root@<device> --export)"` derives `JETKVM_HOST` + `JETKVM_AUTH_TOKEN` from the one ssh connection, so a device is driven with no committed hostname and no hand-copied token.

**Closes / relates to:** a follow-up to `opencharly/layer-charly-check#15` / `opencharly/plugin-jetkvm#5`; documents `opencharly/charly-jetkvm#1`.

**Breaking change + rollback:** `none` — skill prose. Revert the merge to roll back.
