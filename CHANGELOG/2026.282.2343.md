# 2026.282.2343 — chore(gitignore): ignore .check/ run state — 30 disposable beds write there and nothing catches it (#455)

## Summary

This repo's root `charly.yml` declares **30 disposable beds**, and it has **no root `.gitignore` at all** — so a bed run writes `.check/<bed>/<calver>/` into the working tree with nothing ignoring it. Every session that follows the rulebook's `git status`-first discipline sees noise the repo does not own, and any broad `git add` would commit it.

**`opencharly/opencharly#455` took the census** that this fix acts on. Keyed per repo to `origin/main` — because a local census of this class returns a confident wrong number (the umbrella's checkouts lag their own `main` by weeks):

| `charly` | 38 | present | **yes** |

**Three roots ship disposable beds and ignore nothing — 60 beds. This is one of them.**

## The change

A root `.gitignore` carrying `.check/`, with the reason written in it — the same pattern as `charly`'s own, which both documents the class and ignores it.

## How tested

The proof is the file's actual boundary, not a reading of it:

```console
$ git check-ignore -v .check/demo/2026.000.0000/summary.yml
.gitignore:5:.check/	.check/demo/2026.000.0000/summary.yml
```

and after a bed writes real run state, `git status --short` reports nothing — which is the thing this repo's sessions were previously unable to rely on.
